## Result

The clean `sample_book-14` release-candidate pipeline completed successfully.
All eight chapters were scripted, voiced, validated, mastered, and exported as
one chapterized M4B. The run produced no failed or flagged segments, all
segment/master hashes verify, and managed GPU/model services were released.

listening audit before this output is treated as a perceptual release baseline.

## Decisions and next gates

1. Audit the final M4B for the previously reported echo/smearing. Include long
   narration, several character voices, and transitions between them.
2. Review the 14 join warnings, starting with the 16.82 dB chapter-4 boundary
   and the four zero-gap warnings. Record `pass` or a specific audible defect;
   do not tune gain or crossfades from the metric alone.
3. Spot-check dialogue-tag ownership and voice continuity in chapters 4, 7,
   and 8, where attribution fixes and most join warnings are represented.
4. If listening passes, treat `7e46a00` plus the UI-only `4d14810` as the
   release candidate and tag/archive its artifact hashes. If it fails, preserve
   this output and fix only the proven audible failure before a targeted rerun.
5. For performance work, profile TTS generation latency and shorten repeated
   scripting attribution retries. A deterministic contradiction should move to
   exact-evidence repair/fallback after the first failed retry instead of paying
   for several equivalent full model retries.
