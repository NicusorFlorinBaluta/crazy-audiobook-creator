# Full-book E2E run — 2026-08-09

**Status:** Historical record — A dated record of what was done and why. Evidence, not a specification -- do not implement from it.

## Result

The full `sample_book.epub` pipeline completed successfully on Windows with the
AMD/ROCm voice environment. All eight chapters were scripted, voiced,
validated, mastered, and exported as one chapterized M4B.

> **Post-run audio incident:** later listening found widespread echo-like voice
> smearing. The export is valid structurally but is not a perceptual quality
> baseline. Root cause and remediation are documented in
> [audio-echo-incident-2026-08-10.md](audio-echo-incident-2026-08-10.md).

This was a live repair-and-resume run, not a clean benchmark. The observed wall
clock was 16:10:28–23:09:03 Europe/Bucharest (6:58:35), including voice review,
diagnosis, source changes, tests, and controlled service restarts. Use the
per-stage timings below for performance comparisons.

## Issues proven and fixed during the run

1. Installing `faster-whisper` changed `auto` backend selection. CTranslate2's
   CUDA path is not the ROCm TTS path, so the validator backend is now explicit
   for AMD/ROCm. Bootstrapping and TTS were working before this environment
   change; the migration introduced the selection regression.
2. The validator eagerly reloaded the 1.7B TTS model after final validation and
   before returning the completed chapter. The native process exited at that
   unnecessary GPU handoff. TTS now remains lazy-loaded at the next synthesis
   boundary.
3. NumPy boolean values inside `QualityResult.metrics` were not JSON-native and
   prevented the first validation-cache write. Analyzer output is now normalized
   to native Python scalars, with a serialization regression test.
4. Silero preprocessing erased valid short/high-pitched lines and dropped
   repeated words. A controlled seven-clip comparison showed raw `large-v3`
   transcribing all intended speech while the VAD path produced false failures.
   Raw OpenAI Whisper is now the AMD/ROCm default; optional VAD falls back to raw
   audio when it detects no speech. WER thresholds were not loosened.
5. Validation now uses `spoken_text` when that is the deterministic text sent to
   TTS, while preserving authored source text.
6. Managed voice-server stdout/stderr is persisted to
   `brain/projects/voice-server-managed.log` for native-runtime diagnosis.
7. The selected narrator voice (`narrator_male` in this run) is now carried into
   mastering and its dependency fingerprint. Chapter announcements no longer
   assume a literal `narrator.wav` alias.
8. Mastering and export response schemas now retain join diagnostics and the
   book loudness report instead of silently discarding fields the pipeline uses.
9. The dashboard quality API now reports `accepted_with_warning` separately
   instead of misclassifying those segments as failures.
10. Pipeline background completion now clears durable `running` state, avoiding
    a stop/completion race at safe boundaries.

## Follow-up improvements

1. **TTS throughput:** synthesis consumes about 86% of successful generation
   time. Focus profiling on Qwen generation length, attention implementation,
   and ROCm/MIOpen workspace allocation. The run emitted repeated MIOpen fallback
   warnings, including requests near 500 MiB. Do not add parallel GPU workers
   until peak VRAM and model thread safety are measured.
2. **Join-quality review:** expose the 63 join diagnostics as chapter/line links
   in the UI and audition the worst level deltas. Consider local per-segment
   gain matching or slightly longer crossfades only after listening evidence.
3. **Metrics clarity:** rename the log-level `cache_hits`/`cache_misses` labels to
   `validation_cache_hits`/`validation_cache_misses`, and add synthesis cache
   counts. The response model already distinguishes validation cache; the log
   label is ambiguous.
4. **Progress telemetry:** scripting previously reported zero elapsed time, and
   generation exposed `current_line_id` while legacy `current_line` stayed null.
   Consolidate progress fields and add stage-specific ETA based on observed
   words/s, seconds of generated audio, and recent segment latency.
5. **Checkpoint durability:** validation-cache writes are end-of-chapter. Safe,
   incremental accepted-line commits would reduce revalidation after a native
   process exit without weakening generation fingerprints.
6. **Bootstrap reference selection:** avoid highly repetitive, emphatic samples
   as canonical references when clearer real dialogue exists. Starling required
   multiple strict-WER attempts before producing a usable reference.
7. **Scripting speed:** Pass 2 took 89.6 minutes. Preserve the current coverage
   gates, but benchmark fewer/larger chunks, prompt-token reduction, and model
   residency/KV-cache behavior. Quality must be compared, not inferred from
   speed alone.
